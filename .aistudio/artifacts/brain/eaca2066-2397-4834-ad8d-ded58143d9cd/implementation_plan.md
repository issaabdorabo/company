# خطة إصلاح مصادقة Google وفحص Firebase والمزامنة السحابية (نسخة GitHub)

تهدف هذه الخطة إلى حل أخطاء المصادقة الظاهرة في اللقطتين (`تم إلغاء نافذة تسجيل الدخول` و`API key not valid`) المرتبطة ببناء التطبيق عبر GitHub، مع التحقق من إعدادات مشروع Firebase الحالي وتأمين المزامنة بين الأجهزة واسترداد البيانات والعمل دون إنترنت.

---

## مراجعة المستخدم والقرارات المؤكدة

> [!IMPORTANT]
> بناءً على إجاباتك، تم تحديد السبب الجذري لأخطاء المصادقة واعتماد المسار التالي للتنفيذ:

- **طريقة التثبيت (بناء عبر GitHub)**: مستودع GitHub يستثني ملف التوقيع `debug.keystore` عبر قواعد التجاهل، ما يجعل البناء الخارجي يوقّع الحزمة بشهادة `SHA-1` مختلفة عن البصمة المسجّلة في مشروع Firebase، وهو ما يؤدي إلى إلغاء نافذة Google Sign-In ورفض مفتاح الـ API (`API key not valid`) عند محاولة تسجيل الدخول عبر المتصفح.
- **مسار إصلاح Firebase**: فحص مشروع Firebase الحالي وإعادة التحقق من قواعد الأمان وإعدادات المشروع، مع إضافة أداة فحص فورية داخل التطبيق لكشف بصمة الشهادة الفعلية ومطابقتها وإعدادات GitHub Actions لفك ملف التوقيع المشفّر `debug.keystore.base64` تلقائياً أثناء البناء.
- **الأولويات المؤكدة**:
  1. التحقق الدقيق من المزامنة السحابية بين الجهاز الرئيسي والأجهزة الفرعية.
  2. استرداد البيانات السحابية على الهاتف بدون أخطاء.
  3. تجاوز إجبار التوثيق تماماً عند العمل بدون إنترنت.

---

## ١. النظرة العامة والمفهوم الأساسي

- **ماذا تقدم هذه الترقية**: تضمن تطابق توقيع الحزم المبنية عبر GitHub مع بصمة التطبيق المعتمدة في Firebase، وتزوّد شاشة «التحقق والاختبارات» في الإعدادات بفحص متكامل لشهادة التوقيع، ومفتاح الـ API، وحالة الربط بين الرئيسي والفرعي، وسلامة استرداد البيانات السحابية، مع عمل محلي كامل دون إنترنت.
- **المستفيدون**: مديرو المخازن والموظفون الذين يثبتون التطبيق من مستودع GitHub على هواتفهم ويعملون في بيئات متصلة أو منقطعة عن الإنترنت.
- **القيمة الأساسية**: التخلص التام من خطأ `API key not valid` وفشل تسجيل الدخول بحساب Google، مع رؤية تشخيصية واضحة لحالة السحابة والأجهزة المرتبطة.

## ٢. تجربة المستخدم والتصميم المرئي

- **التدفقات الرئيسية للمستخدم**:
  1. **الفتح والعمل بدون إنترنت**: يقلع التطبيق مباشرة على لوحة التحكم بالوضع المحلي الكامل دون أي حظر أو شاشات دخول إجبارية؛ وتبقى كل عمليات المخازن والأصناف والسندات والنسخ الاحتياطية المحلية فعالة.
  2. **شاشة التحقق والاختبارات في الإعدادات**:
     - يعرض قسم الاختبارات بنداً جديداً لفحص **توقيع التطبيق وبصمة SHA-1 وإعدادات Firebase** مقارنةً بالبصمة المعتمدة، مع زر واحد لنسخ البصمة الفعلية للهاتف في حال البناء بمفتاح خاص جديد.
     - عند حدوث أي رفض من خادم Firebase أو خدمات Google Play، تتحول رسائل الخطأ الإنجليزية التقنية إلى تشخيص عربي واضح يبيّن هل السبب عدم تطابق بصمة التوقيع أم تقييد مفتاح الـ API أم اتصال الشبكة.
     - يظهر فحص مباشر لحالة **المزامنة بين الرئيسي والفرعي** (عدد الأجهزة المربوطة ونشاطها في الرئيسي، وحالة الصلاحيات والعضوية في الفرعي).
  3. **استرداد البيانات السحابية**: زر استرداد آمن في مركز الربط السحابي يراجع السجلات قبل تطبيقها ويعرض تقريراً واضحاً بعدد السجلات المستعادة دون تعطل أو فقدان بيانات.
- **الهوية البصرية والمظهر**:
  - الحفاظ على تصميم Material Design 3 الداعم للغة العربية (RTL) والثيمات الستة الفاخرة، مع مؤشرات حالة لونية واضحة (أخضر للنجاح، برتقالي للوضع المحلي/التحذير، أحمر للأخطاء الحرجة) ومساحات لمس لا تقل عن `48dp` واحترام الحواف الآمنة للشاشة (`enableEdgeToEdge` و`WindowInsets`).

## ٣. القرارات الفنية والمفاضلات

- **القرار ١ — توحيد توقيع بناء GitHub عبر أتمتة البناء وفحص الشهادة الحي**:
  - *النهج المختار*: إضافة سير عمل GitHub Actions يفك شهادة التصحيح المشفرة المتوفرة مسبقاً في المستودع قبل التجميع، مع فحص حي داخل التطبيق يقرأ بصمة الشهادة المثبتة فعلياً على الهاتف ويقارنها بالبصمة المسجلة في Firebase.
  - *لماذا*: يحل المشكلة من جذورها عندما يُبنى التطبيق على خوادم GitHub، ويكشف فوراً للمستخدم إذا بُنيت النسخة بمفتاح مختلف.
  - *البدائل المستبعدة*: إزالة `debug.keystore` من قواعد التجاهل أو تعديل إعدادات التوقيع الأساسية، لأن ذلك قد يربك أو يكسر تهيئة بيئة البناء القياسية.

- **القرار ٢ — فحص وإصلاح مشروع Firebase الحالي بدلاً من استبداله**:
  - *النهج المختار*: التحقق من نشر قواعد Firestore على قاعدة البيانات المسماة والتحقق من توافق إعدادات مشروع Firebase الحالي، وتحويل أخطاء `API key not valid` و`GetCredentialCancellationException` إلى تشخيص دقيق مع الحفاظ على التدفق المزدوج للمصادقة (Credential Manager ثم متصفح Google OAuth كبديل).
  - *لماذا*: يحافظ على بيانات المشروع الحالية وقاعدة البيانات السحابية الموحدة دون قطع الارتباط عن المستخدمين الحاليين.

- **القرار ٣ — تحصين الاسترداد والمزامنة والوضع المحلي**:
  - *النهج المختار*: جعل استرداد البيانات السحابية يتم داخل معاملة ذرية محصّنة (`withTransaction`) تتحقق من صلاحية الجلسة وتدفق التبعيات (المخازن والأصناف والسندات ثم الأرقام التسلسلية للوحدات المصروفة والمتاحة)، وإبقاء جميع العمليات السحابية محجوبة تماماً عند انقطاع الإنترنت أو غياب التوثيق.
  - *لماذا*: يمنع أي تلف أو تعارض في البيانات أثناء الاسترداد على الهاتف ويضمن استقرار التطبيق دون إنترنت.

## ٤. البنية التقنية واستراتيجية البيانات

- **مخطط البنية وتدفق التحقق والمزامنة**:

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                         شاشة الإعدادات والتحقق                          │
│  ┌──────────────────────┐   ┌────────────────────┐   ┌───────────────┐  │
│  │ فحص التوقيع والـ API  │   │ التوثيق بحساب Google│   │ تحكم رئيسي/فرعي│  │
│  │ (SHA-1 & Config Check)│   │ (CM -> OAuth Fallback)│   │ واسترداد سحابي│  │
│  └──────────┬───────────┘   └─────────┬──────────┘   └───────┬───────┘  │
└─────────────┼─────────────────────────┼──────────────────────┼──────────┘
              │                         │                      │
              ▼                         ▼                      ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        طبقة العرض (InventoryViewModel)                  │
│  • فحص الشهادة الفعلية للحزمة مقارنة ببصمة Firebase المسجلة               │
│  • ترجمة أخطاء Identity Toolkit / Credential Manager إلى تشخيص عربي      │
│  • منع أي استعلام سحابي عند عدم التوثيق أو العمل بدون إنترنت            │
│  • اختبار المزامنة (الرئيسي <-> الأجهزة الفرعية) والتحقق من الاسترداد    │
└─────────────┬───────────────────────────────────────────┬───────────────┘
              │ (وضع محلي بدون إنترنت دائماً)               │ (عند التوثيق والاتصال)
              ▼                                           ▼
┌──────────────────────────────┐            ┌─────────────────────────────┐
│   قاعدة البيانات المحلية     │            │    مستودع السحابة الموحدة     │
│        (Room DB v6)          │◄──────────►│  (Firestore Named DB)       │
│  مخازن • أصناف • سندات • وحدات│  استرداد/   │  قواعد أمان محققة + أجهزة   │
│  معاملة ذرية محصنة للاسترداد │   مزامنة     │  فرعية بصلاحيات منفردة     │
└──────────────────────────────┘            └─────────────────────────────┘
```

- **ربط المكونات التفاعلية بالحالات**:
  - **تشغيل الاختبارات والتحقق**: يفحص سلامة Room، حالة الشبكة، تطابق بصمة `SHA-1` الحالية مع بصمة Firebase، حالة توثيق Google، استجابة قاعدة Firestore وقواعدها، وحالة مزامنة الأجهزة الفرعية/الرئيسية.
  - **نسخ بصمة التوقيع**: يتيح نسخ البصمة الظاهرة على الهاتف مباشرة إلى الحافظة لتسهيل إضافتها في وحدة تحكم Firebase عند البناء بمفاتيح إصدار مخصصة.
  - **استرداد البيانات السحابية**: يتحقق من وجود قاعدة مملوكة، يسحب كافة السجلات النشطة (بما فيها حالات الوحدات الفردية)، ويطبّقها بأمان مع عرض عدد السجلات المستردة أو سبب التعذر بوضوح.
  - **تجاوز إجبار التوثيق**: تبقى جميع شاشات المخزون والحركات والتقارير والنسخ الاحتياطي الهاتفي متاحة بالكامل في وضع عدم الاتصال، ولا يتوقف المستخدم عند أي شاشة ربط أو تحقق.
